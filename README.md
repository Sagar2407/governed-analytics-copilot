# Governed Analytics Copilot — Synthetic Data

A fully synthetic, reproducible B2B-SaaS data warehouse that backs a **correctness and
governance benchmark** for a natural-language analytics copilot.

The copilot's premise: a business user asks a question in plain English; an LLM proposes a
*structured query plan* (never raw SQL); a deterministic compiler validates it against a
governed metric layer, injects the caller's row-level entitlements, executes it, and
returns an answer with lineage. To prove such a system is *correct* and *safe*, you need
data with **known ground truth** and **deliberate, documented traps**. That's what this
generates.

## Why synthetic (on purpose)

A correctness benchmark needs ground truth you control — you can't verify "the copilot got
NRR right" against real data where nobody has computed the true NRR under your exact metric
definitions. So the data is generated by a **seeded** simulator and every headline metric is
**independently recomputed** (see `generator/reference_metrics.py`) from the raw tables.
Two seeds produce two independent **fixtures**, so a query that is "right by luck" on one
fails on the other.

No real people, companies, credentials, or PII: names are Faker-generated and emails use
the reserved `.example` TLD (RFC 2606).

## Quick start

```bash
pip install -r requirements.txt

# build both fixtures (fixture_a=seed 42, fixture_b=seed 1337) at medium scale
python run.py

# fast tiny build for testing
python run.py --scale smoke --fixtures a=42

# larger build
python run.py --scale large

# inspect a fixture: coherence checks + a live demo of every trap
python scripts/inspect_fixture.py data/fixture_a
```

Each fixture lands in `data/<fixture>/`:

```
data/fixture_a/
  warehouse.duckdb          # all tables (+ a reference.* schema of gold metrics)
  manifest.json             # config, row counts, full schema, headline KPIs, quirks
  tables/*.csv              # every table as CSV
  tables/*.parquet          # every table as Parquet
  reference_metrics/*.csv   # independently-computed gold metric time series
```

## What's in the warehouse (23 tables, ~830k rows at medium)

A mid-size (~$40–55M ARR) B2B SaaS company's GTM + finance data:

- **Entities:** `accounts` (with org hierarchy, region/segment, internal flag),
  `users` (internal GTM org), `account_ownership` (SCD2 with transfers), `plans`,
  `calendar`, `fx_rates`.
- **Revenue:** `subscriptions`, `subscription_events` (the MRR-movement bridge),
  `revenue_schedule` (monthly recognition), `contracts`, `invoices`,
  `invoice_line_items`, `payments`, `refunds`.
- **Pipeline:** `opportunities`, `opportunity_stage_history`,
  `opportunity_snapshots` (weekly point-in-time, leakage-free).
- **Activity:** `end_users`, `usage_events` (local + UTC timestamps), `daily_usage`,
  `support_tickets`.
- **Governance:** `access_map` (per-user entitlements), `personas` (demo switcher).

See [`docs/DATA_DICTIONARY.md`](docs/DATA_DICTIONARY.md) for column-level detail and metric
definitions.

## The traps (each has a documented "correct handling" in `manifest.json → quirks`)

| Trap | Where | Correct handling |
|------|-------|------------------|
| Multi-currency | `invoices`, `opportunities`, … | never `SUM(amount_local)` across currencies; use `amount_usd` |
| Internal/test accounts | `accounts.is_internal` | exclude from customer/revenue metrics |
| Fan-out + duplicate rows | `invoices → invoice_line_items` | aggregate to invoice grain / dedupe by `line_item_id` |
| As-of ownership | `account_ownership` | attribute via `valid_from/valid_to`, not `is_current` |
| Timezone boundaries | `usage_events` | group by `event_local_date` (that's how `daily_usage` rolls up) |
| Late-arriving data | `usage_events.loaded_at` | recent periods may be incomplete; history is settled |
| Void / pending invoices | `invoices.status` | exclude `void`; `pending` = billed-not-collected |
| Refunds / credits | `refunds` | net = gross − refunds; state which you report |
| NULLs | `accounts.industry`, `opportunities.lead_source` | bucket as "Unknown", don't drop rows |
| Metric separation | ARR vs bookings vs recognized | pick the right measure for the question |

## Row-level security demo

`personas` maps demo personas to real internal users; `access_map` holds their entitlement
grants. The copilot's compiler will translate a caller's grants into injected row filters.
`scripts/inspect_fixture.py` shows the scoping live, e.g.:

```
Finance (Global)            scope=all              sees 395/395 accounts
Account Executive           scope=owned_accounts   sees  24/395 accounts
Regional Sales Manager - EMEA  scope=region=EMEA   sees 110/395 accounts
Account Team - <account>    scope=account=...      sees   1/395 accounts
```

## Reproducibility

A given seed reproduces a byte-identical fixture: all randomness flows through one seeded
numpy `Generator` and one seeded `Faker`. Scale presets (`smoke`/`small`/`medium`/`large`)
change volume only, not structure.
